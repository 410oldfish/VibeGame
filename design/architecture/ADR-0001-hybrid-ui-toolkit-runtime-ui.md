# ADR-0001：运行时 UI 采用 UI Toolkit / uGUI 混合架构

- 状态：Accepted
- 日期：2026-08-06
- 决策者：VibeGame 团队

## 背景

项目固定使用 Unity 6000.4.7f1。现有屏幕空间界面由 uGUI、TMP、Prefab 和运行时 `GameObject/AddComponent` 混合构造；单位、遗迹血条则是世界空间 Canvas。战斗 HUD 的手牌刷新会销毁并重建全部视图，冒险控制器同时承担状态、命令和界面构造职责。

本次迁移必须保持战斗结算、地图生成、网络命令和公开玩法 API 不变，并允许按功能逐步回归。

## 决策

1. 屏幕空间运行时 UI 的目标实现为 UI Toolkit。
2. 单位、状态和遗迹等世界空间 UI 暂时保留 uGUI；`com.unity.ugui` 不删除。
3. 迁移期间两套系统通过 `IBattleHudView` 等内部视图边界共存。控制器拥有状态与命令，视图只渲染只读展示模型并转发用户意图。
4. UI Toolkit 使用一个共享的 `PanelSettings`、1920×1080 参考分辨率、公共 USS 设计令牌和简体中文动态字体。
5. 手牌以 `runtimeId` 作为稳定键进行增量更新；拖拽继续把屏幕坐标交给 `HexBattleController.EndCardDrag`，不改世界目标判定。
6. 模态根节点拦截点击；普通透明布局节点使用 `PickingMode.Ignore`。

## 选择理由

UI Toolkit 更适合当前大量屏幕空间、数据驱动的 HUD、列表和模态界面，并能用稳定元素复用减少 uGUI 的 GameObject 创建与 GC。世界空间 UI Toolkit 在本项目的 Unity 安装中已存在 `PanelRenderMode.WorldSpace`、`UIRenderer` 和世界空间输入 API，但这部分能力较新，现阶段替换生产血条的回归收益不足。

## 被否决的方案

- 一次性删除 uGUI：世界空间条、混合输入和所有交互同时回归，风险不可接受。
- 继续扩展程序化 uGUI：无法解决控制器耦合和全量重建问题，维护成本继续增长。
- 首批迁移世界空间 UI：技术可行，但不是当前性能和维护痛点。

## 结果

正面影响：屏幕 UI 获得统一主题、响应式布局、稳定元素身份、可测试视图边界和列表虚拟化能力。

代价：迁移期需要同时维护两种 UI 技术；焦点、事件优先级和模态穿透必须纳入回归测试。

## 验证与回滚

- 在 1280×720、1920×1080、2560×1440、3440×1440 下验证布局和最小 18px 主文字。
- PlayMode 覆盖按钮状态、列表数量、回调、模态关闭与手牌拖拽。
- Profiler 要求静止 HUD 无持续 GC，状态变化不重建无关手牌元素，CPU/UI 渲染不得比基线恶化 10% 以上。
- 每个视图均保留独立旧实现，迁移功能可在控制器创建视图的位置切回，不影响玩法状态。

## 知识与工具链风险

仓库目前没有架构注册表或引擎参考目录。本决策依据 `ProjectVersion.txt`、本机 6000.4.7f1 的 `UnityEngine.UIElementsModule.xml` 以及 Unity 官方版本说明验证；后续升级 Unity 时应重新执行世界空间 UI 单组件技术验证。
