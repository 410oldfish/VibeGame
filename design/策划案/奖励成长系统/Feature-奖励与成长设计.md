# 《VibeGame》奖励与成长设计

> **文档状态**：草案 v0.3  
> **Layer**：Feature
> **Priority**：MVP  
> **关联总案**：[`../游戏粗略策划案.md`](../游戏粗略策划案.md)  
> **Quick reference**：关键依赖 冒险系统、战斗系统、职业系统、卡牌构筑

## Summary

奖励与成长系统定义战斗胜利、商店、事件与休息处四类成长入口的系统职责，以及奖励如何作为构筑修正器。具体章节投放节奏与商品内容见 同目录 Feature 层文档。

## 1. 文档定位

本文件是奖励与成长系统的主文档，负责定义玩家在战斗、商店、事件和休息处中如何获得成长，并说明成长系统如何反向塑造构筑方向。

本文件负责：

- 战斗奖励的类别和投放方向（职责层面）。
- 商店与服务的系统职责。
- 事件与休息处提供的成长入口（职责层面）。
- 成长节奏与系统学习节奏之间的关系（原则层面）。

本文件不负责：

- 地图节点如何生成。
- 牌组生命周期与战斗时序。
- 原型测试数值本身。

## 2. 玩家体验目标

- 让奖励节奏逐步引入位置、地形与敌方牌局相关玩法。
- 让商店、事件与休息处共同承担构筑修正和风险管理功能。
- 让成长系统不仅提升数值，还扩大玩家改写战场规则的能力。
- 奖励是构筑修正器：补充位移、净化、打断或地形工具以修正路线缺口。

## 3. 详细设计

### 3.1 核心规则

#### 战斗奖励

战斗胜利后，奖励系统接收战斗结果并分发对应成长入口。

奖励类别包括：金币、卡牌奖励、副职业奖励等；具体投放节奏与章节引入顺序见 [`Feature-商店与服务设计.md`](Feature-商店与服务设计.md) 及 [`../冒险系统/Feature-章节主题设计.md`](../冒险系统/Feature-章节主题设计.md)。

#### 商店与服务

商店的职责不只是卖东西，还包括帮助玩家修正构筑。可售内容类型包括卡牌、装备、道具、删除/附魔/升级服务及情报类服务；具体商品见 同目录 Feature 层文档。

#### 事件与休息处

- 特殊事件应围绕长期风险与收益提供选择。
- 休息处应承担恢复、强化与战前准备功能。
- 具体事件选项与休息处服务见 同目录 Feature 层文档。

#### 成长节奏原则

奖励系统的目标不是让所有复杂机制同时出现，而是按章节和节点类型逐步引入；第一章优先学习移动、站位和基础地形交互，中后期再引入高影响地形连锁、敌方牌组干涉和玩法改写效果。具体章节映射见 Feature 层文档。

### 3.2 状态与流转

| 入口 | 触发 | 产出 |
| --- | --- | --- |
| 战斗奖励 | 战斗胜利 | 金币、卡牌等待选奖励 |
| 商店 | 进入商店节点 | 购买与服务 |
| 事件 | 进入事件节点 | 长期收益/代价 |
| 休息处 | 进入休息节点 | 恢复/强化/合成 |

### 3.3 与其他系统的交互

| 类型 | 主要内容 |
| --- | --- |
| 上游依赖 | 冒险节点、战斗结果、职业内容池、构筑方向、遭遇难度 |
| 系统产出 | 金币、卡牌、道具、装备、服务、长期收益与代价 |
| 下游影响 | 玩家构筑修正、职业成长路线、后续路线选择与风险判断 |

## 4. 边界情况

- **本文只定义奖励系统职责**，不定义商品价格和原型最终数值。
- **若未来加入局外长期成长、遗物或元进度**：需单独作为成长子系统扩展。
- **奖励系统不能为了丰富而过早投放过多高复杂度机制**。

## 9. 验收标准

- **GIVEN** 战斗胜利，**WHEN** 奖励流程启动，**THEN** 由奖励系统（而非战斗系统）分发成长入口。
- **GIVEN** 玩家进入商店节点，**WHEN** 交互完成，**THEN** 构筑修正通过商店服务生效且不影响战斗时序规则。
- **GIVEN** 原型阶段，**WHEN** 查看 Content 投放表，**THEN** 第一章不包含完整三章的全部高复杂度机制。
