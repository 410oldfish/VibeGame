# 《VibeGame》冒险地图与关卡设计

> **文档状态**：草案 v0.3  
> **Layer**：Feature
> **Priority**：MVP  
> **关联总案**：[`../游戏粗略策划案.md`](../游戏粗略策划案.md)  
> **Quick reference**：关键依赖 职业系统、奖励成长、遭遇系统、战斗系统

## Summary

冒险系统组织单局 Roguelike 的章节路线、节点类型与战斗场景生成入口，连接职业选择后的局外流程与战斗/服务节点。章节主题节奏与学习曲线见同目录下其他 Feature 层文档。

## 1. 文档定位

本文件是冒险系统的主文档，负责定义章节推进、路线选择、节点结构和战斗场景生成入口。

本文件负责：

- 章节结构与路线地图。
- 节点类型与节点职责。
- 章节环境主题的组织方式（接口与职责，具体主题见 Content）。
- 战斗场景在进入战斗前需要准备的关卡信息。

本文件不负责：

- 战斗中的公共时序与空间规则。
- 奖励数值、商店价格或原型数值假设。
- 敌人牌组的具体行为逻辑。

## 2. 玩家体验目标

- 让局外路线选择与局内战斗环境形成连续的策略节奏。
- 让每章都具备逐步强化的环境主题。
- 让玩家在节点选择阶段就开始思考后续战斗、奖励与风险。
- 路线选择驱动构筑变化：因未来战斗、奖励与风险修正而产生抉择，而非单纯「走格子」。

## 3. 详细设计

### 3.1 核心规则

#### 章节路线结构

- 每章沿用 `10 行 4 列` 的纵向路线结构。
- 玩家团队共同选择路线，不拆分为多个小队。
- 每章最后一个节点汇入首领战斗节点。

#### 节点类型

| 节点类型 | 主要作用 |
| --- | --- |
| 普通战斗 | 提供基础战斗学习、资源获取和卡牌奖励 |
| 精英战斗 | 检验构筑方向，提供更高风险和更高收益 |
| 首领战斗 | 作为章节终局，集中检验阶段性成长结果 |
| 商店 | 提供卡牌、装备、道具与构筑修正服务 |
| 特殊事件 | 提供高波动的长期收益、代价或规则变化 |
| 休息处 | 提供恢复、强化和战前准备空间 |

#### 战斗场景生成入口

进入战斗节点时，冒险系统需要为战斗系统准备以下内容：

- 地图轮廓。
- 固定地形。
- 互动设施。
- 单位出生区域。
- 环境规则。

具体生成规则与参数见 [`Feature-战斗场景生成规则.md`](Feature-战斗场景生成规则.md)。

### 3.2 状态与流转

| 状态 | 进入条件 | 退出条件 | 行为 |
| --- | --- | --- | --- |
| 章节进行中 | 进入某章首节点 | 击败章首领或本局失败 | 沿路线推进 |
| 节点选择 | 到达分支点 | 团队确认下一节点 | 写入路线进度 |
| 战斗入口 | 进入战斗类节点 | 战斗结算完成 | 输出场景参数给战斗系统 |
| 服务节点 | 进入商店/事件/休息 | 服务交互结束 | 移交奖励系统 |

### 3.3 与其他系统的交互

| 类型 | 主要内容 |
| --- | --- |
| 上游依赖 | 职业选择结果、章节配置、节点池、关卡主题、奖励系统支持的服务类型 |
| 系统产出 | 下一节点选择、战斗场景参数、节点事件入口、章节推进结果 |
| 下游影响 | 战斗系统收到什么战场、奖励系统在什么节点发放什么内容、遭遇系统如何编排内容 |

## 4. 边界情况

- **本文不定义战斗内移动、敌方意图、状态结算和奖励数值细节**。
- **若未来加入分队、岔线剧情或章节外地图结构**：需单独扩展冒险系统，不写入总纲。
- **场景生成只定义生成输入**，不负责具体战斗内结算。

## 9. 验收标准

- **GIVEN** 玩家处于章节路线中，**WHEN** 团队选择下一节点，**THEN** 所有队员同步进入该节点类型对应流程。
- **GIVEN** 进入战斗类节点，**WHEN** 冒险系统完成场景准备，**THEN** 战斗系统收到地图轮廓、固定地形、出生区与环境规则五类输入。
- **GIVEN** 到达章末节点，**WHEN** 路线结构有效，**THEN** 该节点为首领战斗类型。
- **GIVEN** 玩家进入商店/休息处/特殊事件节点，**WHEN** 团队确认，**THEN** 移交奖励系统对应服务流程并返回路线地图。
- **GIVEN** 第一章地图生成完成，**WHEN** 校验节点约束，**THEN** 至少含 1 商店、2 休息处、3 事件入口且满足 [`Feature-节点与服务设计.md`](Feature-节点与服务设计.md) §2.1 间距规则。
