# 《VibeGame》状态、技能与道具联动规则

> **文档状态**：草案 v0.3  
> **Layer**：Foundation
> **Priority**：MVP  
> **关联总案**：[`../游戏粗略策划案.md`](../游戏粗略策划案.md)  
> **Quick reference**：关键依赖 战斗系统、敌人系统、地形系统、职业系统、联机系统

## Summary

状态效果系统为战斗、敌人、地形和道具提供统一的语义与结算时机协议。玩家通过状态理解「何时生效、如何影响移动与敌方意图」；**已投入登记**见 [`../设计规范/Feature-已投入设计词条登记.md`](../设计规范/Feature-已投入设计词条登记.md)，Foundation 增益/减益表同时记录全量候选词条与当前运行时实现状态。

## 1. 文档定位

本文件是状态效果系统的主文档，负责定义状态、技能、道具和跨系统效果在战斗中的语义边界与结算关系。

本文件负责：

- 状态在系统层面的分类与用途。
- 关键时机点与结算顺序。
- 状态对敌人意图、地形、技能和道具的影响。
- 词条表与系统语义之间的对应关系。

本文件不负责：

- 每个状态的完整数据表 → [`Feature-已投入设计词条登记.md`](../设计规范/Feature-已投入设计词条登记.md)；全量备选见 Foundation 增益/减益 **参考表**。
- 技能与道具的职业具体数值。
- 地形词典、敌方牌组词典和战斗时序本体。

## 2. 玩家体验目标

- 让现有状态词条直接服务于位置、地形和敌方意图三大核心机制。
- 让技能、状态与道具在不同系统之间使用统一的解释框架。
- 减少「已展示意图」和「尚未执行效果」之间的规则争议。
- 状态词条表与系统语义分离：词条表记录数据，本文件解释跨系统含义。
- 效果时机（如「回合开始时」「进入地形时」「执行意图前」）作为多系统之间的接口协议，必须统一。

## 3. 详细设计

### 3.1 核心规则

#### 核心联动状态

现有增益状态与减益状态词条已覆盖大量战术效果，其中与新核心机制最直接相关的状态包括：

| 系统 | 相关状态 | 用途 |
| --- | --- | --- |
| 移动控制 | 稳固、飞行、束缚、缠绕、残废、恐惧、诱惑 | 改变路径、位移收益和地形风险 |
| 防御站位 | 格挡、圣盾、戒备、嘲讽、隐身 | 保护关键格或操纵敌方目标 |
| 地形属性 | 燃烧、感电、中毒、石化、无实体 | 支撑地表反应与伤害类型 |
| 持续伤害 | 流血（每打出一张牌时按层数自伤，不自动清除）、燃烧（回合开始伤害并减半）、中毒（回合开始伤害并减 1） | 战士卖血体系与消耗品异常 |
| 敌方出牌干涉 | 眩晕、冰冻、沉默、封印、混乱 | 打断或改变敌方公开意图 |

#### 技能与道具的系统语义

- 技能应优先放大职业在移动、地形改装或敌方意图干涉方面的战术身份。
- 道具应作为跨职业补足手段，让非专精职业也能有限度地处理环境问题。
- 同一个关键词在卡牌、技能和道具中的结算语义应尽量保持一致。

#### 待统一的争议规则

后续需要优先统一以下交界问题：

- 打断类状态是取消本次意图、延后执行，还是改为弃牌。
- 沉默、封印、混乱等效果影响已公开意图，还是只影响下次生成。
- 强制位移导致目标或施术者脱离合法范围时，敌方牌如何结算。
- 地形伤害、持续状态与意图执行的先后顺序如何统一。

### 3.2 状态与流转

本系统无独立顶层状态机；各状态词条在战斗回合阶段内按时机点触发。关键时机点包括：回合开始、进入地形、执行意图前、回合结束等，具体优先级见 [`../战斗系统/Core-战斗系统.md`](../战斗系统/Core-战斗系统.md) 与待补充的「状态时机与优先级规则」子文档。

### 3.3 与其他系统的交互

| 类型 | 主要内容 |
| --- | --- |
| 上游依赖 | 战斗时序、敌方意图、地形规则、职业技能、道具来源 |
| 系统产出 | 状态生效结果、目标可行动性变化、地形/意图修正、技能与道具的统一语义 |
| 下游影响 | 玩家回合决策、敌人执行结果、地形反应时机、联机同步事件类型 |

## 4. 边界情况

- **若高层说明与已实现词条明细冲突**：当前版本以 Foundation 增益/减益表中标记为“已实现”的运行时核对记录为准，并同步修正高层说明；计划状态仍以设计登记为准。
- **若未来加入更复杂的持续效果堆栈、触发器链或事件总线**：需新增专门的效果时序文档，不得继续堆叠在本文件。
- **若道具系统形成独立成长体系**：应另立系统文档，不继续挂在本文件下。
- **若打断类状态与敌方公开意图同时生效**：按 [`../敌人系统/Feature-敌人牌组与意图机制.md`](../敌人系统/Feature-敌人牌组与意图机制.md) 与本文待统一规则处理；未拍板前标 `[待确认]`。

## 9. 验收标准

- **GIVEN** 战斗进入玩家行动窗口且敌方意图已公开，**WHEN** 玩家对敌人施加眩晕，**THEN** 系统按已拍板的打断规则处理该意图（取消/延后/弃牌），且与敌人系统文档一致。
- **GIVEN** 单位进入带燃烧覆盖的地形，**WHEN** 触发「进入地形时」时机，**THEN** 按地形系统与状态词条统一语义施加对应状态。
- **GIVEN** 同一关键词出现在卡牌与道具描述中，**WHEN** 结算该效果，**THEN** 使用相同的系统语义，不出现双标准解释。
