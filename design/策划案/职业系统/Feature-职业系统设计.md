# 《VibeGame》职业系统设计

> **文档状态**：草案 v0.2  
> **Layer**：Feature
> **Priority**：MVP  
> **关联总案**：[`../游戏粗略策划案.md`](../游戏粗略策划案.md)  
> **Quick reference**：关键依赖 卡牌构筑、地形、敌人、奖励成长

## Summary

职业系统定义职业选择在流程中的位置、所有职业共用的组成要素，以及职业与构筑/战斗/地形/敌人的连接方式。单职业数值与牌表见 Content 条目文档。

## 1. 文档定位

本文件是职业系统的主文档，负责定义职业在整个游戏中的共性结构，以及职业系统与构筑、战斗、地形、奖励等系统的连接方式。

本文件负责：

- 职业选择在游戏流程中的位置。
- 职业的共用组成要素。
- 职业与牌组、技能、属性、成长之间的关系。
- 单职业文档的统一记录方式。

本文件不负责：

- 某个职业的具体卡牌数值。
- 某个职业的完整技能条目细节。
- 战斗中的公共回合时序与空间规则。

## 2. 玩家体验目标

- 让每个职业都具备清晰可识别的战术身份。
- 让职业差异真正体现在位置、地形、敌方意图和资源使用方式上。
- 让单职业文档可以围绕统一结构持续扩展。
- 身份由系统交互共同构成：战斗中的职责、构筑路线、地形用法、对敌方牌局的应对方式。
- 共性规则与个体条目分离，新增职业只需遵守统一模板。

## 3. 详细设计

### 3.1 核心规则

#### 职业选择

- 游戏开始时，每个玩家先选择一个职业。
- 职业选择确定角色的基础属性、初始牌组、技能结构和后续可获得内容池。
- 多人模式下，各玩家可以选择不同职业，以形成不同的战场职责分工。

#### 职业的共用组成

每个职业至少由以下部分组成：

| 组成 | 说明 |
| --- | --- |
| 初始属性 | 生命、能量、体力等基础战斗资源 |
| 关键词 | 描述该职业的主玩法语言与设计方向 |
| 技能 | 主动或被动的职业能力，强化其战术身份 |
| 初始牌组 | 决定开局可执行策略和构筑起点 |
| 成长方向 | 职业在奖励选择后可能分化出的路线 |

#### 职业身份约束

- 职业系统应优先定义「怎么打」，而不是只定义「数值高低」。
- 职业强项应与战场位置、地形互动或敌方意图应对方式直接相关。
- 单职业的弱项应真实存在，从而为队友配合和构筑修正留出空间。

### 3.2 状态与流转

| 阶段 | 行为 |
| --- | --- |
| 开局选择 | 确定职业与初始构成 |
| 冒险成长 | 通过奖励扩展牌组与技能 |
| 战斗表现 | 按职业身份承担战场职责 |

### 3.3 与其他系统的交互

| 类型 | 主要内容 |
| --- | --- |
| 上游依赖 | 角色选择入口、构筑规则、奖励投放、状态词条、地形与敌人机制 |
| 系统产出 | 初始属性、初始牌组、职业技能、关键词、成长方向、职业专属奖励池 |
| 下游影响 | 玩家战斗风格、构筑路线、地形使用方式、队伍协作定位 |

## 4. 边界情况

- **本文不记录单职业完整数值与完整牌表**。
- **若未来加入副职业、双职业或角色外观系统**：应在职业系统之外单独建文档。
- **若职业成长做成局外长期系统**：需新增成长接口文档。

## 9. 验收标准

- **GIVEN** 新职业条目文档，**WHEN** 按模板填写，**THEN** 包含初始属性、关键词、技能、初始牌组、成长方向五类组成。
- **GIVEN** 玩家开局选职，**WHEN** 进入冒险，**THEN** 携带该职业的初始属性与牌组进入后续系统。
