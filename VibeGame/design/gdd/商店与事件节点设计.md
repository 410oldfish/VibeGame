# 商店与事件节点设计

## 目标

在现有六角冒险地图中加入类似《杀戮尖塔》的非战斗决策节点，让玩家在战斗之外通过金币、生命值和牌组质量进行长期取舍。

本次实现包含商店节点和事件节点的可玩 MVP，并复用现有 `HexRunState`、职业卡池、地图推进和 Overlay UI。

## 玩家体验

### 商店节点

玩家进入商店后看到本次访问固定生成的 8 个职业可用卡牌商品：

- 商品按卡牌稀有度和能量费用定价。
- 同一商品只能购买一次，购买后显示为 `Sold`。
- 金币不足时购买按钮不可用。
- 每次商店访问可使用一次删牌服务，价格为 50 金币。
- 删牌界面展示当前牌组中的前 16 张牌；选中后永久移除该牌并返回商店。
- 玩家可以不消费并直接离开，离开后该地图节点结算完成。

### 事件节点

每次进入事件节点时，从当前事件池随机抽取一个事件。界面展示事件文本、当前生命和金币，以及三个带明确后果的选择。

已实现事件：

| 事件 | 主要选择 |
|---|---|
| 遗忘神龛 | 牺牲 12% 最大生命换 55 金币；获得随机卡；离开 |
| 流浪医师 | 25 金币恢复 30% 最大生命；45 金币增加 5 最大生命并治疗 5；离开 |
| 废弃货车 | 损失 10% 最大生命换 45 金币；获得随机卡；离开 |

带生命代价的选择不能让玩家死亡；金币不足的付费选项不可选。选择结算后事件节点立即完成，避免重复领取。

## 规则

### 商店库存

1. 进入节点时调用职业奖励卡池生成不重复的候选牌。
2. 商品价格计算：
   - 普通：32 金币基础价。
   - 罕见：52 金币基础价。
   - 稀有：75 金币基础价。
   - 每点能量费用增加 3 金币，最终附加 `-4～+4` 的小幅浮动。
3. 库存和售出状态只在当前商店访问中存在；离开节点后销毁。
4. 买牌和删牌均由 `HexShopSession` 原子结算金币与牌组，UI 不直接修改运行状态。

### 事件结算

1. `HexAdventureEventSession` 保存一次事件的标题、描述、选项和已结算状态。
2. 选项可组合两个基础效果：金币、治疗、伤害、最大生命和随机卡牌。
3. 所有生命变化均被限制在 `1～maxHealth`；事件伤害不会致死。
4. 同一事件会话最多成功结算一次。
5. 随机卡牌沿用当前职业奖励池，不会越过现有职业限制。

## 数据与调参

当前 MVP 使用代码内事件定义，核心调参位置为：

- `HexShopSession.CardRemovalPrice`：删牌价格。
- `HexShopSession.GetCardPrice`：卡牌价格曲线。
- `HexAdventureEventSession.CreateForgottenShrine`：神龛代价和奖励。
- `HexAdventureEventSession.CreateWanderingHealer`：治疗价格与幅度。
- `HexAdventureEventSession.CreateAbandonedWagon`：货车风险与奖励。
- `HexAdventureMapGenerator.PickNodeTypeForFloor`：地图中事件和商店的出现率。

后续事件数量明显增加时，应将事件文本、选项和数值迁移到 ScriptableObject 或配置表；行为枚举和结算器可继续复用。

## UI 与反馈

- 地图沿用 `$` 表示商店、`?` 表示事件。
- 商店顶部持续显示金币、牌组数量或删牌服务状态。
- 已售商品显示 `Sold`，不可购买商品自动禁用。
- 事件选择直接写明成本和收益；不满足条件时按钮禁用。
- 本次沿用现有 Adventure Overlay、商品卡、通用选项和底部按钮 Prefab，不新增美术资源。

## 边界情况

- 奖励卡池不足 8 张时，只展示实际生成的商品。
- 商店不能删除牌组中的最后一张牌。
- 同一次商店只能删牌一次。
- 满生命时仍可购买治疗，但实际恢复量为 0；这是允许玩家主动浪费金币的明确选择。
- 事件伤害选项仅在当前生命严格大于伤害值时可用。
- Overlay 被重建时，商店会话继续保留，因此从删牌界面返回不会刷新库存或清除售出状态。

## 依赖与影响

- 运行状态：`HexRunState.gold/currentHealth/maxHealth/deckDefinitions`。
- 卡牌来源：`HexCardLibrary.GetRewardChoices` 和 `GetRandomRewardCard`。
- 地图推进：`HexAdventureController.CompleteRoomAndReturnToMap`。
- UI：UGUI、TextMeshPro 及现有 `Assets/Resources/UI/Adventure` Prefab。
- 本次不改变网络同步、存档结构和战斗规则；多人权威结算与跨会话存档仍属于后续范围。

## 验收标准

- [x] 地图能够生成并进入商店、事件节点。
- [x] 商店生成职业匹配且不重复的卡牌库存。
- [x] 成功购买会扣除金币、加入牌组并锁定商品。
- [x] 金币不足或商品已售时不能购买。
- [x] 每个商店可付费删除一张牌，且不能删除最后一张牌。
- [x] 事件会从至少三种遭遇中随机生成。
- [x] 事件选择能够组合金币、生命、最大生命和卡牌结果。
- [x] 不满足金币或安全生命条件时，事件选项不可用。
- [x] 完成商店或事件后节点被标记访问并返回地图。

## QA 用例

1. 给运行状态注入足够金币，连续点击同一商品两次，确认只扣款并加牌一次。
2. 金币低于商品价格时进入商店，确认对应按钮不可交互。
3. 删除一张牌后回到商店，确认金币减少 50、牌组减少 1，删牌服务不可再次使用。
4. 多次开始新冒险并进入事件，确认三种事件都可出现。
5. 将生命设置为等于事件伤害值，确认风险选项不可用；高于伤害值时可用且结算后至少剩 1 HP。
6. 分别验证治疗、增加最大生命、获得金币和获得随机卡的运行状态变化。
7. 从商店直接离开、从事件选择离开，确认地图当前节点推进且只能进入后继节点。
